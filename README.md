# 电台播出与版权窗口排程

一个不依赖第三方包、使用 SQLite 和标准库 HTTP 服务的电台排程项目。系统把“计划排期”和“实际播出”分开保存，支持地区授权、日期窗口、禁播时段、节目冷却、赞助商间隔、直播临时替换、实播对账与版权越界检查。节目资料按版本保存：每次修改生成不可变新版本，排期钉住当时的版本，旧版本只留给历史。

## 分层

- `catalog.py`（节目维护）：创建节目、生成新版本、追加授权地区。新版本生成后触发未播排期重查。
- `scheduling.py`（排期判定）：所有校验只读取传入的节目版本；负责排期、替换、改版重查与“仍可播起点”推算。
- `database.py`（存储与对账）：连接、schema、旧库迁移、实播登记和对账；对账一律按排期钉住的版本取资料。
- `app.py` + `static/index.html`（页面操作）：HTTP 接口与操作页面。

## 改版规则

修改节目（时长、授权窗口、地区、赞助商、冷却）时生成新版本并自动重查该节目的未播排期：

- 重查通过：排期改为引用新版本，状态保持 `planned`。
- 重查失败：排期退回 `needs_revision`，记录原时段（日期、起点、原时长）、失败原因、候选版本和当日“仍可播起点”；没有可行起点时记为 `null`（如地区已完全未授权）。
- 已做直播替换（`replaced`）或已有实播记录的排期不重查，永久钉住当时版本；对账和页面都按当时资料显示。
- 编播可在页面或 `POST /api/slots/{id}/revise` 用新起点/新地区对退回排期重新判定，通过即换用新版本。

## 运行

需要 Python 3.11+。

```bash
python app.py
```

默认端口为 `8111`，页面地址是 <http://127.0.0.1:8111>。第一次启动会创建 `radio.db` 并写入三条演示排期。也可以设置端口和数据库位置：

```bash
PORT=9000 RADIO_DB=/tmp/radio.db python app.py
```

## 测试

```bash
python -m unittest discover -s tests -v
```

测试覆盖完整流程：排期、临时替换、播放日志、按日期对账；同时覆盖时间重叠、未授权地区和实播错节目等失败场景。

## 主要 API

- `GET /api/state`：节目（含版本列表）、排期（含钉住版本号与待改信息）和最近对账异常
- `POST /api/programs`：创建节目并授权地区（生成 v1）
- `POST /api/programs/{id}/revise`：修改节目资料，生成新版本并重查未播排期；请求体只传需要改的字段（时长、授权起止、赞助商、冷却、`regions` 整组替换）
- `POST /api/programs/{id}/regions`：追加一个授权地区（同样生成新版本）
- `POST /api/schedule`：按节目当前版本创建排期
- `POST /api/slots/{id}/replace`：替换计划节目并重新校验，排期钉住替换时的版本
- `POST /api/slots/{id}/revise`：对 `needs_revision` 排期用新起点/新地区重新判定
- `POST /api/playout`：登记实播记录（有实播记录的排期不再参与改版重查）
- `POST /api/reconcile`：按日期生成漏播、错播、时长偏差和超授权异常，全部按排期钉住版本核对

改版接口返回 `report`：`upgraded`（已替换引用的排期）、`needs_revision`（退回待改，含原时段、原因、仍可播起点）、`locked`（已替换或有实播、保持历史版本的排期）。

准备排期时填写 `air_date`、`start_time`、`program_id`、`region`。页面会直接显示校验错误，不会保存失败的排期。旧版数据库首次启动时自动迁移为版本化结构，历史排期钉住迁移出的 v1。
